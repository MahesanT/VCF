Build journey

1

Prepare the physical ESXi hosts

Both hosts were upgraded to ESXi 8.0 U3. A standard vSwitch named vSwitch-Holo was created with MTU 9000, vmnic2 as the 10 Gb uplink and a VLAN 4095 trunk port group named Holo-Trunk.

esxcli network vswitch standard add -v vSwitch-Holo
esxcli network vswitch standard set -v vSwitch-Holo -m 9000
esxcli network vswitch standard uplink add -v vSwitch-Holo -u vmnic2
esxcli network vswitch standard portgroup add -v vSwitch-Holo -p Holo-Trunk
esxcli network vswitch standard portgroup set -p Holo-Trunk -v 4095
esxcli network vswitch standard portgroup policy security set -p Holo-Trunk -a true
esxcli network vswitch standard portgroup policy security set -p Holo-Trunk -m true
esxcli network vswitch standard portgroup policy security set -p Holo-Trunk -f true
2

Build shared NFS storage

A second 10 Gb direct link on vmnic3 was dedicated to NFS. VMkernel interfaces were configured as 10.77.20.1 and 10.77.20.2 with MTU 9000. An Ubuntu NFS VM at 10.77.20.10 exported /srv/nfs/holodeck to both ESXi hosts.

vmkping -I vmk1 -s 8972 -d 10.77.20.2

# Ubuntu NFS export
/srv/nfs/holodeck 10.77.20.1(rw,sync,no_subtree_check,no_root_squash) 10.77.20.2(rw,sync,no_subtree_check,no_root_squash)

# Mount from each ESXi host
esxcli storage nfs add -H 10.77.20.10 -s /srv/nfs/holodeck -v Holo-Shared
3

Deploy HoloRouter and configure Holodeck

HoloRouter 9.0 was deployed with both Site A and Site B trunks connected to Holo-Trunk. Holodeck was pointed at the existing vCenter, cluster, shared datastore and trunk network.

Start-HoloDeckPrecheck -Version "9.0"

New-HoloDeckInstance `
  -Version "9.0" `
  -ManagementOnly `
  -ProvisionOnly

The provisioning run created four nested ESXi VMs and the VCF Installer appliance. The generated management-domain specification was stored at /holodeck-runtime/specs/management_domain_config_spec_for_vcf_installer.json.

Offline Depot: the key troubleshooting win

The online depot initially authenticated successfully but individual VCF binaries such as NSX and Fleet Management returned HTTP 403. The final solution was to use the newer Software Depot ID → Activation Code workflow with VCF Download Tool 9.1.1.

Install VCF Download Tool 9.1.1 side-by-side

mkdir -p ~/vdt-9.1.1
tar -xzf ~/vcf-download-tool-9.1.1.0.25713929.tar.gz -C ~/vdt-9.1.1
~/vdt-9.1.1/bin/vcf-download-tool --version

# Generate the Software Depot ID
~/vdt-9.1.1/bin/vcf-download-tool configuration generate --software-depot-id

List and download only VCF Installer Day-0 binaries

~/vdt-9.1.1/bin/vcf-download-tool binaries list   --depot-download-activation-code-file=/home/admin/vcf-activation-code.txt   --vcf-version=9.0.0   --sku=VCF   --automated-install   --type=INSTALL

~/vdt-9.1.1/bin/vcf-download-tool binaries download   --depot-download-activation-code-file=/home/admin/vcf-activation-code.txt   --depot-store=/home/admin/vcf90-depot   --vcf-version=9.0.0.0   --sku=VCF   --automated-install   --type=INSTALL

Result: 7 binaries downloaded successfully, roughly 53 GB total.

sudo cp -a /home/admin/vcf90-depot/PROD/. /var/www/build/PROD/
sudo chown -R nginx:nginx /var/www/build
sudo chmod -R 750 /var/www/build

Resolve DNS / NTP validation mismatches

The VCF Installer initially used 10.77.10.129 for DNS/NTP while the Holodeck JSON expected 10.77.1.1. The persistent settings were corrected before the final validation run.

sed -i 's/^DNS=10\.1\.10\.129$/DNS=10.77.1.1/'   /etc/systemd/network/10-eth0.network

sed -i 's/^server 10\.1\.10\.129$/server 10.77.1.1/'   /etc/ntp.conf

networkctl reload
networkctl reconfigure eth0
systemctl restart systemd-resolved
systemctl restart ntpd

resolvectl status eth0
ntpq -pn

What I learned

Nested networking matters

VLAN 4095 trunking, promiscuous mode, forged transmits and MAC changes are foundational for a nested VCF environment.

Storage must be truly shared

A direct 10 Gb NFS design gave both physical hosts access to the same Holodeck datastore and avoided pinning the nested management domain to a single host.

Depot authentication ≠ entitlement

The online depot could authenticate while protected binaries still returned 403. The newer Software Depot ID / Activation Code flow solved the actual download authorization problem.
